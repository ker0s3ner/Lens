0.6.513 — Fourier

This patch improves call-graph responsiveness and expands fileless/shared-memory analysis.

  • Bound direct callee and jump-table target collection before sorting or expanding graph nodes.
  • Keep switch-target inspection bounded separately from function call targets.
  • Warn when per-function target, instruction, caller, or node limits may hide graph relationships.
  • Report edge truncation only when an additional distinct edge was omitted.
  • Recover prototypes for aligned allocation, array reallocation, and POSIX memory allocation.
  • Recover prototypes for memory mapping, remapping, advice, residency, locking, and process-break APIs.
  • Recover prototypes for POSIX and System V shared memory, `memfd`, descriptor execution, and file allocation APIs.
  • Classify memory and shared-memory APIs in runtime behavior events.
  • Identify shared/anonymous-memory imports as a distinct static capability.
  • Correlate the capability with runtime code loading as a heuristic; the imports alone do not prove a call path or malicious behavior.
  • Count `fexecve` as process execution and runtime code loading.
  • Use a 12 KiB ELF file with two 64 MiB virtual-only segments in the large-file gate.
  • Verify file-backed and zero-fill segment sizes and enforce a 256 MiB peak-RSS ceiling; GitHub measured 0.008 seconds at 13.82 MiB peak RSS on the 12,288-byte fixture (one synthetic run).
  • Run the large-file gate automatically when its workflow, fixture, or core loader/report code changes on `main`.
  • Weighted IDA Pro parity remains 41.8%; the 50% target remains unmet.

GitHub Actions builds the release artifact; no local build or installation was performed.
