Documentation

Lens is a disassembler, decompiler and debugger for macOS. This page covers everything in the app.

Install

  1. Download Lens-macos-arm64.zip from the latest release.
  2. Unzip and drag Lens.app into /Applications or ~/Applications.
  3. Right-click the app and choose Open the first time. The build is ad-hoc signed and not notarized, so macOS asks for confirmation once.
Put the app in a folder you can write to. Updates replace the app in place and need write access to its folder.

Open a program

Drop a file onto the window, use Open a program, or press Cmd+O. Lens detects the compiler, language, packer and calling convention by itself. Universal Mach-O files ask which slice to read. Recent files appear on the start screen.

Updates

Lens checks GitHub for a newer release when it starts (turn this off in Settings). You can also choose Tools > Check for updates.

  • Up to date: a small card says so and fades away after a few seconds.
  • Update available: a card shows the version and what changed. Choose Download and install, or Later (a button stays in the toolbar).
  • Downloading: the card shows a progress bar with the percentage, then unpacks and verifies the signature.
  • Restarting: Lens swaps in the new version and reopens itself. Your notes, names and patches are kept.

Navigate and annotate

  • G jumps to an address or name. Enter follows the target under the cursor, Esc goes back.
  • N renames, ; adds a note, M bookmarks, X lists everything that uses the item, P turns the cursor into a function.
  • Names, notes, bookmarks and patches are saved per program and come back when you reopen it.

Search

Cmd+F opens Search with five modes: Listing (instruction text), Strings, Names, Bytes (hex pattern, ?? for any byte) and Number. Results are capped at 3,000 and the search stops after a few seconds on huge files. Click a result to jump to it.

Hex to code

Tools > Hex to Code turns bytes into instructions. Paste hex text (spaces, 0x prefixes and \x41 escapes are fine), or load a .bin, Intel HEX or Motorola S-record file. Choose the CPU, byte order and base address, then read the listing, copy it, or choose Open as program to get the full analysis, graph and pseudocode.

Patching

Tools > Patch bytes lists every change you made. You can write raw hex, NOP an instruction, invert a conditional branch or turn it into an unconditional jump. Patches are stored with the program and re-applied each time you open it, and each can be reverted. Save patched copy writes a new file; on macOS it is re-signed ad hoc so it still launches. The original is never modified.

Structs

Tools > Structs takes plain C declarations (struct Header { uint32_t magic; char name[16]; void *next; };), computes offsets and lets you lay a struct over data at an address. Field names then show up as names in the listing.

Prototypes and constants

Analysis > Function Prototypes holds about 190 built-in C signatures (libc, POSIX, sockets, threads, parts of Win32 and macOS) and lets you add your own, such as int check_license(const char *key, int len);. The pseudocode uses them in four ways: a call gets exactly the right number of arguments, a function marked noreturn ends its code path, the result of a call gets its declared type (char *v5;), and a function that has a prototype is printed with your types and parameter names.

Magic numbers in arguments are also named for the program's operating system: open(path, 0x602) reads open(path, O_RDWR | O_CREAT | O_TRUNC), and short strings such as "r" are shown where a char * is expected. Constant names exist for open, mmap, lseek, socket, signals and the main Win32 memory and file calls.

Analysis extras

Rename variables by double-clicking one in the pseudocode; the name is remembered for that function. Switch tables are recovered across x86, ARM/Thumb, ARM64, RISC-V, MIPS and PowerPC common patterns: each case becomes an edge in the graph and a case N: line in a switch in the pseudocode. Vtable/RTTI discovery recognizes conservative executable-pointer runs and common Itanium headers. Function starts are read from Mach-O function-start tables, ELF .eh_frame and PE .pdata, so stripped programs lose fewer functions. Crypto constants (AES, SHA-1/256/512, MD5, CRC-32, Blowfish, ChaCha, Base64 and others) are found in the bytes and listed under Lists > Crypto and in the overview. Lists shows functions, names, imports, exports, entry points, strings, sections, crypto findings and bookmarks. Compare programs diffs two versions by function. Import reads names and notes from Lens JSON, IDA .idc or Ghidra .py scripts, and Export writes IDC, Ghidra, JSON, map, listing (.asm) and Graphviz call-graph files. Edit > Undo and Redo (Cmd+Z, Cmd+Shift+Z) cover names, notes, bookmarks, structs, functions and prototypes.

Signatures

Learn signatures from a file asks you to pick an unstripped program or library, then records the first instructions of every named function in it (addresses are masked out, so relocated copies still match) and saves them to your signature folder. Recognise library functions then names matching functions in any other program, which is how stripped binaries get their library calls back. Ambiguous matches are dropped rather than guessed.

No signature library ships with Lens yet. Learn from an unstripped build of a library to create your own.

Debugger

Tools > Debugger runs the program under lldb (included with the Xcode command line tools). Tick the confirmation box first: the debugger really runs the program.

  • Set breakpoints with F2; they show as red dots in the listing.
  • Run, continue, step into, step over, pause and stop. The current instruction is highlighted and the registers update at every stop.
  • Addresses are translated between the file and the running (slid) process automatically.
Apple-protected system binaries cannot be debugged (SIP), and the program's own stdin is not connected.

Scripting and plugins

Scripts use Rhai. Open Tools > Script, type, and run. Plugins are .rhai files in the plugins folder (see Settings and data); they appear under Tools > Plugins, and a plugin that defines fn on_open() runs every time a program finishes loading.

// name every function that references the string "password"
for s in strings() {
    if s.text.contains("password") {
        for x in xrefs_to(s.addr) {
            comment(x, "uses: " + s.text);
        }
    }
}
log("done: " + functions().len() + " functions");

Scripts are limited to 40 million operations so a runaway loop cannot freeze the app.

Fonts, keys and assistants

Open Settings with Cmd+,. It has five tabs.

  • Fonts. Pick the code size, a code font and an interface font from the ones installed on your Mac, or point Lens at any .ttf or .otf file. The code font should be monospaced.
  • Keys. Every shortcut in the list can be changed. Click Change, press the keys, done. Lens refuses a combination that another action already uses. Reset puts one back, Reset all puts everything back.
  • Assistants. Lens can hand the function under the cursor to another tool. Claude Code (claude -p) and Codex (codex exec) are set up for you, and you can add any command. Lens sends your question and the decompiled function to the command on standard input and shows what it prints in the Assistant window (Cmd+L). {file}, {func} and {addr} are filled in, so open -a Cursor {file} works too (untick the answer box for apps that just open). The Test button checks the command exists. Claude Code and Codex must be installed and signed in on your Mac.
  • Updates and General. Theme, interface size, string length and update checks.
Privacy. The function text goes only to the command you configured. Lens itself sends nothing anywhere except the update check to GitHub.

Menu bar

The macOS menu bar has File, View, Navigate, Analysis, Assistant, Window and Help. Everything in the command palette (Cmd+P) is also there, and plugins you install appear under Analysis > Plugins.

Limitations

  • Lens is young. Expect rough edges on very large, obfuscated or unusual binaries.
  • Pseudocode on non-x86 CPUs covers integer code only; MIPS delay slots are not modelled; Thumb is available through Hex to Code only.
  • No type recovery, switch-table recovery or vtable recovery yet. See the roadmap.
  • The debugger needs lldb and cannot attach to protected system binaries.
  • Builds are Apple Silicon only and ad-hoc signed.

Building and releasing

cargo run --release                 # run from source
./scripts/bundle-macos.sh           # build dist/Lens.app and the zip

# publish: bump version in Cargo.toml, commit, push, then
git tag v0.3.0 && git push origin v0.3.0

Pushing a v* tag starts the GitHub Actions workflow, which checks the tag matches Cargo.toml, builds on an Apple Silicon runner and attaches Lens-macos-arm64.zip to a release. Installed copies pick it up through the update card.
